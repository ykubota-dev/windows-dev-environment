# F01 クリップボード履歴 — 要件・製造方針

- 対象：Windows 11
- 実装ブランチ：`develop/windows-clipboard`
- 方針：**A案（状態確認とGUI操作案内）**
- 現在の段階：要件・製造方針の整理。機能本体は未実装。

## 1. 背景・目的

新しいWindows端末でクリップボード履歴（`Win + V`）を使えるようにするため、設定状態の確認と必要な手動操作を、セットアップ受付画面から一貫して案内する。基本設計書・詳細設計書で定義済みの「状態確認とGUI操作案内」に準拠する。

## 2. 初版のスコープ

### 実施する

1. `scripts/setup.ps1` からF01を選択できること（既存の受付画面を利用）。
2. Windows 11および必要な実行環境を確認すること。
3. **信頼できる取得方法が確認できた場合のみ**現在の有効／無効状態を表示すること。判定できなければ「未確認」と明記し、推測しない。
4. 有効化が必要な場合は、Windowsの設定画面または `Win + V` を使う操作手順を日本語で案内すること。
5. `-DryRun` では確認予定・案内予定のみ表示し、設定変更やファイル書込を行わないこと。
6. 利用者が実施する操作と、アプリ側で検証できた結果を明確に分けて表示すること。
7. F01の結果を既存の `FeatureId`／`Status`／`Message` 形式で返すこと。状態を確認できない、または手動操作が必要な場合は `ManualRequired` とする。
8. 再実行してもWindows設定を変更せず、安全に同じ案内ができること。

### 初版では実施しない

- レジストリ、グループポリシー等を直接変更してクリップボード履歴を自動有効化する処理
- 管理者権限への昇格、組織ポリシーの回避
- クリップボードの内容・履歴の取得、削除、クラウド同期
- 設定ファイルのバックアップや復元（初版は設定変更をしないため対象外）

## 3. 実行フロー

1. `setup.ps1` でF01を選択。
2. 実行予定と「変更は自動実施しない」旨を表示。
3. 対象OS／環境を確認。
4. 可能であれば現在状態を取得。取得手段が不確実な場合は「未確認」。
5. 有効なら操作不要と案内。無効または未確認ならWindowsの設定画面／`Win + V` での手順を案内。
6. 自動的に確認できた事実と手動確認が必要な事項を区別して結果表示。
7. 次の選択機能へ進む。既存のYes／Skip／Cancelの意味と承認ルールは維持する。

**注意：** OS内部の設定値のみで有効・無効を断定できるかは実装前に検証する。根拠が不十分なら必ず `ManualRequired` にフォールバックする。利用者の操作が必要な状態で `Success` と誤表示しない。

## 4. 製造順序

1. **調査・方式確定**：Windows 11でのGUI操作経路、状態判定可否、PowerShellの互換性を確認。
2. **機能モジュール**：`scripts/features/F01-clipboard.ps1` に状態確認と日本語操作案内を実装。状態判定処理はテストで差し替えられるよう分離。
3. **Controller統合**：`scripts/setup.ps1` でF01選択時に呼び出し、既存の結果集約に接続。
4. **DryRun対応**：状態変更・ファイル変更なしで予定を確認できることを保証。
5. **自動テスト**：Pesterで有効／無効／判定不能／取得エラー／DryRun／Skip／Cancel／再実行を検証。Windows状態の取得はモック化。
6. **手動確認**：Windows 11のPowerShell 7で表示、操作手順、結果表示を確認。変更されないことを確認。
7. **CI・レビュー**：PSScriptAnalyzer／Pesterが通った状態でPRを作成し、利用者がマージ。

## 5. 完了条件

- F01を受付画面から実行でき、日本語で必要な操作が分かる。
- 状態を確認できない場合は不明と扱い、誤って有効と断定しない。
- `-DryRun`・通常実行のいずれもWindows設定を自動変更しない。
- Pester・静的解析・Windows実機確認が完了している。
- 既存F02〜F05のプレビュー動作を壊していない。

## 6. 将来の拡張

自動有効化（B案）を採用する場合は**別の設計変更とPR**に分ける。対象Windowsバージョン、適用API／レジストリの根拠、管理ポリシーへの対応、承認、バックアップ・復元、適用後検証を先に設計する。
