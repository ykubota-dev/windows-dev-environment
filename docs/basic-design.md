# 基本設計書

- 文書ID：BASIC-001
- 対象：windows-dev-environment
- バージョン：0.3
- 状態：基盤改修・F01実装済み
- 対象OS：Windows 11

## 1. 背景と目的

日常的に使用するWindows開発環境の設定をGitで管理し、新しい端末でも必要な機能を選択して安全に再現できるようにする。手作業による設定漏れを削減し、変更履歴と導入手順を公開可能な形で整理する。

## 2. 対象範囲

| ID | 機能 | 現在の状態 | 適用方式 |
| --- | --- | --- | --- |
| F01 | クリップボード履歴 | 実装済み | 状態確認とGUI操作案内 |

未実装の機能候補：Git Alias、PowerShell Profile、PowerToys、VS Code Settings Sync、wingetアプリ管理、AutoHotkey、Everything。未実装機能にはIDを予約しない。機能の実装時に次の連番を割り当て、既存IDは原則変更しない。Git AliasとPowerShell Profileは独立した設定対象として分ける。

Microsoft IME辞書は別リポジトリで管理する。Windows以外のOS、秘密情報の同期、既存アプリの強制更新・削除は対象外。

## 3. 構成

```text
scripts/setup.ps1
    ├─ 登録済み機能の選択と承認
    ├─ メタデータ（Name / Plan / Script）
    └─ scripts/features/
         └─ F01-clipboard.ps1
```

機能追加時は機能スクリプトを作成し、`setup.ps1` の機能カタログへ登録する。実行先をID別のswitch文で増やさず、登録されたScriptから解決する。実行前に登録IDとファイル存在を確認する。差分表示・バックアップ等は今後の設定変更機能で導入する。

## 4. 運用方式

- デフォルトは対話型の機能選択方式。
- `-Features` による非対話的な対象指定を可能にするが、変更の承認は省略しない。
- ファイル差分、パッケージの導入予定、手動操作の内容を変更前に示す。
- 変更前にバックアップする。明示的承認なしでは変更しない。
- 再実行時に設定を重複させない。
- 実行結果は `Success`、`Skipped`、`Failed`、`ManualRequired` として集約する。

## 5. 非機能要件

| 観点 | 要件 |
| --- | --- |
| 安全性 | 差分表示・明示承認・既存ファイルのバックアップ |
| 冪等性 | 再実行による重複設定・重複導入を防ぐ |
| 可観測性 | 対象・結果・失敗理由・手動対応事項を表示する |
| 保守性 | 機能別モジュールと設定を独立させる |
| 実行環境 | Windows 11、PowerShell 7推奨。事前検査で互換性判定する |
| セキュリティ | トークン・認証情報・端末固有情報をコミットしない |
| 権限 | 昇格が必要なら事前に明示し、組織ポリシーを回避しない |
| 障害時 | 失敗項目を記録し、独立機能の継続可否を判定する |

## 6. 開発フェーズ

1. 基盤・CIの構築およびF01の状態確認・操作案内は実装済み。
2. メタデータ駆動の機能登録を導入し、未実装機能の予約IDを廃止する。
3. Git Alias、PowerShell Profileを別々の機能として順次実装する。
4. その他の機能は必要性と優先度に応じて採番・実装する。

## 7. Git運用

`main` は安定版。機能ごとの `develop/<feature-name>` ブランチからPRを作る。マージはリポジトリ所有者が行う。
