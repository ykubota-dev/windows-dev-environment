# 詳細設計書

- 文書ID：DETAIL-001
- バージョン：0.3
- 状態：F01実装済み・基盤改修

## 1. エントリーポイントとCLI

`scripts/setup.ps1` をセットアップ起点とし、登録済みの機能だけを選択できる。

| コマンド | 動作 |
| --- | --- |
| `.\scripts\setup.ps1` | 対話型機能選択 |
| `.\scripts\setup.ps1 -Features F01` | F01の確認後に実行 |
| `.\scripts\setup.ps1 -Features All` | 現在登録されている全機能を選択 |
| `.\scripts\setup.ps1 -Features F01 -DryRun` | 変更せず計画を表示 |
| `.\scripts\setup.ps1 -Features F02 -DryRun` | 未登録IDとして拒否 |

機能IDは実装時に採番する。未実装機能のIDは予約しない。Git AliasとPowerShell Profileは独立した機能とする。

## 2. 機能カタログとモジュール構成

`setup.ps1` の `$featureCatalog` に、機能IDをキーとして `Name`、`Plan`、`Script` を登録する。現在の登録対象はF01のみ。

```text
scripts/
  setup.ps1
  features/
    F01-clipboard.ps1
  ci/
tests/
  setup.Tests.ps1
  F01-clipboard.Tests.ps1
```

機能の追加時にスクリプトとメタデータを同時に登録する。機能ID別の実行分岐は作らない。IDが未登録なら実行せずエラーとする。登録されたスクリプトが存在しない場合は当該機能をFailedとし、他の機能を継続する。各スクリプトは `FeatureId`、`Status`、`Message` を返す。実行先は信頼できる固定カタログからのみ取得する。

## 3. 機能選択と実行順序

1. 選択した登録済み機能の実行計画を表示する（機能固有の事前チェックは各機能で行う）。
2. 対象機能を複数選択する（CLI引数指定時はその値を使う）。
3. 登録済みカタログの順序で対象スクリプトを解決する。
4. 差分・操作予定・必要な権限を表示し、機能単位で確認する。
5. 変更を伴う機能では、実装時にバックアップ処理を追加する。
6. 各機能の結果を検証して集約する。

将来、同じパッケージの導入が複数の機能で必要になる場合、共通インストール処理で重複を防ぐ。依存機能の失敗は独立機能へ波及させない。

## 4. 差分提示・確認・適用ルール

**設計上の最重要規則：差分を表示し、明示的承認後にのみ変更する。**

対象別のプレビュー：
- ファイル：既存ファイルと変更予定の内容を比較し、追加・変更・削除行を表示。可能ならUnified Diff形式とする。
- パッケージ：既存導入状態、パッケージID、予定操作、ライセンス/権限上の注意点を表示。
- GUI：取得できる現在状態のみ提示。自動判定できなければ「未確認」と明示して手動手順を示す。

確認時の選択肢：

| 選択 | 挙動 |
| --- | --- |
| Yes | 当該変更を承認。変更直前に対象の状態を再検証する |
| Skip | 当該機能を変更せず次へ |
| Cancel | 未実行の変更を中止する |
| Enterのみ・不明な入力 | 承認しない。再入力または安全に中止する |

変更予定と承認時点の状態が変わった場合、**変更を停止して差分を再生成し、再承認を取得**する。承認を他機能へ流用しない。差分のない設定は `Skipped` とする。手動操作が必要な場合は `ManualRequired` を返す。

### バックアップ

- 承認後・書込前に既存ファイルのバックアップを取得する。
- バックアップ先はローカルであり、Gitにコミットしない。
- バックアップ失敗時は当該変更を適用しない。
- バックアップの作成場所、対象、復元手順を実行結果に記録する。
- 既存ファイルがない場合は、新規作成予定としてプレビューする。
- 適用後の検証失敗時は `Failed` とし、安易な自動復元で追加の変更を起こさず復元方法を提示する。

### DryRun

- 読み取り、計画生成、差分表示、適用可否検証のみ許可。
- ファイル作成、バックアップ、レジストリ変更、パッケージの導入・更新は行わない。
- 外部コマンドの状態確認も、副作用のない方法を選ぶ。

## 5. 機能別仕様

### F01 クリップボード履歴（実装済み）
Win + VまたはWindows設定の操作案内。現在状態を正しく検出できない端末では推定せず `ManualRequired` を返す。

### 未実装機能（ID未採番）
Git Aliasは専用設定ファイルを `include.path` で読み込み、既存のGit設定全体を置き換えない。PowerShell Profileは管理対象ブロックだけを追加・更新し、重複を防ぐ。両機能は独立して実装・選択できるようにする。

PowerToys、VS Code Settings Sync、wingetアプリ管理、AutoHotkey、Everythingも未採番とする。具体的な適用方式は各機能の実装PRで定義する。

## 6. 処理結果とエラー制御

機能は少なくとも `FeatureId`、`Status`、`Message` を返す。

```powershell
[PSCustomObject]@{
    FeatureId = 'F01'
    Status    = 'Success'
    Message   = 'Clipboard history checked'
}
```

| Status | 意味 |
| --- | --- |
| Success | 予定した処理・確認が完了 |
| Skipped | 差分なし、対象外、またはユーザーがスキップ |
| Failed | 事前確認、バックアップ、適用、検証などに失敗 |
| ManualRequired | 自動化対象外のユーザー操作が必要 |

通信障害・権限不足・不正な設定ファイル・パッケージ導入失敗などは原因を記録する。秘密情報をログへ出力しない。

| T01 | F01のDryRun | 書き込みなし・計画表示 |
| T02 | All | 登録済みのF01だけを選択 |
| T03 | 未登録ID（F02など） | 入力エラー |
| T04 | 不明なFeature ID | 入力エラー |
| T05 | Allと個別IDの混在 | 入力エラー |
| T06 | Enterのみの承認 | 適用されない |
| T07 | 機能スクリプトの欠損・不正な結果 | 当該機能はFailed |
| T08 | 将来の設定変更機能 | 差分・再承認・バックアップ・冪等性を個別にテスト |

テストにはPesterを想定し、実環境を変更する処理はモック化する。Windows上での結合確認は実装後に実施する。

## 8. Git運用・作業範囲

`main` を安定版とし、`develop/<機能名>` ブランチからPRを作る。機能IDは実装時に採番し、`setup.ps1` へ登録する。未実装機能の予約IDは使用しない。
